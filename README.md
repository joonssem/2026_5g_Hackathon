# 우리의 작은 발명실

초등학교 5학년, 40분씩 2차시 AI 해커톤을 위한 학생 안내 웹입니다. 2인 또는 3인 팀이 문제를 발견하고 해결 방법을 비교하며 Canva Code 요청문을 발전시킵니다.

결과물뿐 아니라 **문제 발견 → 대화 → 해결 방법 비교 → 선택 이유 설명 → 프롬프트 발전** 과정을 학습하는 데 중점을 둡니다. 학생과 담당 교사 모두 처음 사용하는 상황을 기준으로 구성했습니다.

## 수업 페이지

- [학생 활동 페이지](https://joonssem.github.io/2026_5g_Hackathon/): iPad 10세대에서 질문을 읽고 팀의 생각을 기록합니다.
- [전자칠판 안내](https://joonssem.github.io/2026_5g_Hackathon/teacher.html): 교실 앞 65인치 전자칠판에서 시작 안내를 진행합니다.

로컬 실행과 GitHub Pages 배포 방법은 아래에 안내합니다.

## 80분 활동 흐름

| 차시 | 단계 | 권장 시간 |
| --- | --- | --- |
| 1차시 · 생각을 발전시키기 | 01 함께 출발 | 4분 |
| | 02 불편 발견 | 8분 |
| | 03 문제 선택 | 6분 |
| | 04 해결 탐색 | 9분 |
| | 05 프롬프트 완성 | 13분 |
| 2차시 · 만들고 나누기 | 06 Canva로 구현 | 18분 |
| | 07 시험과 개선 | 8분 |
| | 08 Padlet 나눔 | 10분 |
| | 09 생각 돌아보기 | 4분 |

1차시는 팀원이 차례로 의견을 말하고, 해결 방법을 비교해 입력·행동·결과·성공 기준이 분명한 요청문을 완성합니다. 2차시는 핵심 기능 하나를 구현하고 직접 시험한 뒤 친구들과 나눕니다. 권장 시간은 교사가 조정할 수 있으며 단계 이동을 강제하지 않습니다.

## 팀 역할과 두 기기의 사용

- **1번 아이패드:** 안내 웹 읽기, 팀의 생각 기록, 실행 링크 시험, Padlet 게시.
- **2번 아이패드:** 받은 요청문으로 Canva 제작·수정·게시, 실행 링크 전달.
- **3인 팀의 3번:** 자기 생각과 질문을 제안하고, 1번과 함께 1번 아이패드에서 시험.

첫 화면에서 2인 또는 3인 팀을 선택합니다. 3인 팀에는 세 번째 학생의 불편 발견 기록란과 발언 순서가 추가됩니다. 팀 인원을 바꿔도 기존 기록은 남습니다. 역할에 관계없이 모든 팀원이 함께 결정합니다.

여기서 1번·2번·3번은 팀 안의 역할 순서이며 학생의 출석번호가 아닙니다. 3인 팀도 두 아이패드로 활동할 수 있습니다.

요청문은 **1번에서 복사 → Canva 공유 문서에 붙여넣기 → 2번이 같은 문서에서 복사 → Canva Code에 붙여넣기**로 전달합니다. 5단계에서 1번이 Canva 문서(Docs)를 만들거나 교사가 미리 준비한 문서를 열고, **공유 → 조원 초대 → 편집 가능**으로 2번의 학교 계정을 초대합니다. 두 아이패드에서 같은 문서가 함께 편집되는지 확인합니다. 3번은 1번 화면을 함께 보고, 자기 기기를 사용한다면 그 계정도 초대합니다.

공유 문서에는 **요청문 / 실행 링크 / 시험 결과·고칠 점** 칸을 만듭니다. 조원 초대는 Canva 안에서 진행하며 계정 정보를 안내 웹에 입력하지 않습니다. 계정 설정으로 초대가 제한되면 교사가 문서를 만들고 조원을 초대합니다.

시험은 **2번 제작·게시 → 공유 문서에 실행 링크 기록 → 1번에서 링크를 열어 시험**합니다. 1번이 시험 결과·수정 요청을 같은 문서에 적으면 2번이 확인해 수정·재게시합니다. 주소가 바뀌면 문서의 링크도 갱신하고 1번에서 재시험합니다. 안내 웹·공유 문서·실행 도구를 오가며 사용합니다. 공유 문서의 편집 주소는 조원끼리 사용하고 Padlet에는 최종 웹앱의 게시된 실행 주소를 올립니다.

## Padlet 제출 방법

1번 아이패드에서 게시하며, 08단계의 **제목·웹앱 링크·내용 복사 버튼**을 각각 사용합니다.

| Padlet 입력 위치 | 넣을 내용 |
| --- | --- |
| 제목 | 반과 팀 이름. 예: `5학년 1반 · 초록 톱니` |
| 링크 첨부 | Canva로 만든 최종 웹앱의 게시된 실행 주소 |
| 내용 | 1번 아이패드의 활동 기록: 문제와 선택 이유, 해결 방법 A/B, 선택한 방법과 이유, 웹앱 설명·사용 방법. 시험·개선 기록이 있으면 함께 포함 |

**이름과 출석번호는 넣지 않습니다.** 반·팀 이름은 첫 화면에서 입력하고 제출 단계에서 보완할 수 있습니다. 편집용 주소 대신 1번 아이패드에서 시험한 실행 주소를 사용합니다. 본문은 앞 단계의 기록으로 자동 구성되며, 복사해 Padlet 내용 칸에 붙여 넣습니다. 실제 게시 버튼은 학생이 직접 누릅니다.

제출 전에는 웹에서 반·팀 이름·최종 실행 주소·내용을 확인합니다. 제출 양식을 새 탭으로 연 뒤 두 탭을 오가며 제목·링크·내용을 각각 복사해 넣습니다. 작품 감상은 교사가 승인·공개한 뒤 따로 안내한 감상 링크에서 진행합니다. 댓글·좋아요 활동 중에는 Padlet의 댓글 작성자(Commenter) 권한과 댓글·반응을 허용하고, 감상 종료 후 필요하면 읽기 전용(Reader)으로 전환합니다.

## 화면과 글꼴

뉴모피즘의 부드러운 그림자와 들어간 입력란을 사용합니다. 제목은 **Ria**, 본문은 **Paperozi**입니다.

- **학생 iPad:** 본문·대화·요청문 18px, 질문·입력 20px, 보조 설명 16px, 제목 32~42px. 세로 화면에서는 카드를 한 열로 배치합니다.
- **교사 전자칠판:** 별도 6장 안내 화면. 마지막 장의 QR코드로 학생 활동 화면에 접속합니다. 1920px 화면 너비 기준 일반 제목 약 77px, 마지막 장 제목 약 61px, 주요 설명 약 42~48px이며 화면 너비에 맞춰 크기를 조절합니다. 전체 화면 버튼과 이전·다음, ←/→ 및 PageUp/PageDown을 지원합니다.

실제 전자칠판 해상도·배율에 따라 물리적인 글자 크기가 달라지므로 수업 전에 뒷자리에서 확인합니다. 교사용 준비·운영 메모는 학생 페이지 상단의 **교사용 메모**에서 볼 수 있습니다.

## 실행

설치·빌드 없이 HTML/CSS/JavaScript로 실행합니다.

```powershell
python -m http.server 8025 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8025/`를 엽니다. 아이패드 수업에는 HTTPS 배포 주소를 사용합니다. 교사 PC의 localhost 주소는 아이패드에서 열리지 않습니다.

## 수업 전 설정

`config.js`의 `padletClassLinks`에는 사용자 요청에 따라 실제 1~4반 제출 양식 링크를 유지합니다. 각 링크의 section 값이 해당 반 섹션을 지정합니다. 등록된 반은 학생 화면에서 선택할 수 있습니다. 미설정 시 교사에게 링크를 안내받도록 표시합니다. 제출 중에는 **수동 승인**을 켜고 승인을 보류하며, 마감 후 교사가 승인하여 공개합니다. `padletViewUrl`은 추후 전달받을 학생용 전체 보기 링크이며 비워 두면 보기 버튼을 숨깁니다.

전자칠판 마지막 장의 학생 접속 QR코드(`assets/student-page-qr.svg`)와 실제 학생 활동 주소도 수업 운영을 위해 유지합니다.

학생 교육용 계정으로 Canva Docs 조원 초대·공동 편집, Code 생성·게시, Padlet 게시·댓글을 실제 iPad 10세대에서 먼저 확인합니다. 자세한 운영은 [교사 안내](docs/public/TEACHER_GUIDE.md)를 참고합니다.

학교 Wi-Fi 접속, Canva AI 권한·사용량, Padlet 접근 범위·게시·댓글 권한도 확인합니다. 실제 기기에서 공유·붙여넣기와 기록 다운로드를 시험합니다.

## 파일

- `index.html`: 공통 화면, 교사 안내 창
- `app.js`: 9단계 활동, 기록, 요청문·Padlet 글 생성, 복사·기록 내보내기
- `style.css`: iPad 가로·세로 대응 뉴모피즘 디자인
- `typography.css`: 학생 iPad용 읽기·입력 글자 크기
- `teacher.html`, `teacher.css`, `teacher.js`: 65인치 전자칠판용 6장 안내, 전체 화면·키보드 이동
- `fonts.css`: 사용자 지정 Ria 제목 글꼴, Paperozi 본문 글꼴
- `config.js`: 반별 제출 양식(`padletClassLinks`), 추후 전체 보기(`padletViewUrl`) 링크. 반별 소회의실 주소는 공개 저장소에 보관하지 않고 교사에게 별도 안내합니다.
- `docs/README.md`: 문서별 공개·로컬 보관 기준
- `docs/public/DESIGN_LOG.md`: 공개용 요구사항·설계 판단·제작 기록
- `docs/public/TEACHER_GUIDE.md`: 공개용 80분 수업 운영
- `docs/public/VALIDATION.md`: 공개용 검증 결과와 남은 확인
- `docs/public/REVIEW_2026-10-23.md`: 개인정보·구조·수업 흐름·상충 내용 점검 결과
- `docs/private/`: 설문·조 편성 등 로컬 보관용 자료. GitHub 업로드 제외
- `tests/check.mjs`: 학생 활동·기록·복사·Padlet 연결 검사
- `tests/teacher.mjs`: 전자칠판 안내 화면 이동·전체 화면 대안 검사

이 안내 웹의 기록은 같은 기기·브라우저의 localStorage에만 저장되며 Canva 문서나 다른 아이패드에 자동으로 동기화되지 않습니다. 공유할 요청문·시험 결과·기록 전체는 직접 복사해 Canva 공유 문서에 붙여 넣습니다. 그 문서에 적은 내용은 Canva에서 조원과 공동 편집합니다. 마지막 단계에서 기록을 내려받을 수도 있으며, Padlet 게시 버튼은 학생이 직접 누릅니다.


## 검증

별도 패키지 설치 없이 Node.js로 실행합니다.

```powershell
node --check app.js
node --check config.js
node --check teacher.js
node tests/check.mjs
node tests/teacher.mjs
```

두 테스트는 상태와 이벤트 동작을 검사하며 실제 브라우저 렌더링 검사는 아닙니다. 실제 iPad Safari와 65인치 전자칠판의 가독성, 학교 계정에서의 Canva 생성·게시와 Padlet 게시 확인이 필요합니다. 자세한 범위는 [검증 기록](docs/public/VALIDATION.md)을 참고합니다.

## GitHub Pages 배포

Canva 게시 오류 시 학생 코드 게시 기능은 [코드 게시 운영 안내](docs/public/STUDENT_CODE_PUBLISHING.md)를 참고합니다. 08단계의 **게시가 안 되면요?** 안에서 코드를 붙여 넣고 미리보기·게시 후 실행 링크를 받습니다. Supabase 프로젝트와 참여 코드 설정이 필요하며, 무료 프로젝트 일시 중지 중에는 기존 작품 링크도 열리지 않습니다.

GitHub 저장소에 이 폴더의 파일을 푸시하고 **Settings → Pages → Deploy from a branch → main / (root)**를 선택합니다. 최초 설정 후 main에 푸시하면 갱신됩니다. 모든 내부 경로는 상대 경로여서 저장소 하위 주소에서 동작합니다. `.nojekyll`을 포함합니다.

`git remote -v`로 로컬 원격 연결을 확인합니다. 현재 로컬에는 `origin`이 등록되어 있지 않으므로, 아래 예시의 저장소 HTTPS 주소를 실제 대상 주소로 바꿔 푸시합니다. `docs/private/`는 업로드에서 제외합니다.

```powershell
git add .
git commit -m "Update classroom documentation"
git push '저장소 HTTPS 주소' main:main
```

GitHub 푸시와 Pages의 웹 배포 완료 여부는 각각 확인합니다. 이 안내 웹을 그대로 다른 주소로 배포한다면 QR코드와 표시 주소도 함께 갱신합니다.

참고 원본: `참고 프로젝트`의 `index.html`, `docs/SPEC.md`, `assets/app.js`. 원본의 문제 찾기·요청문·시험 문장 흐름을 80분 과정 중심 수업으로 재설계했습니다. 원본 프로젝트가 밝힌 참고: TCA Creator Camp의 PRD·발표 방식, 참고 수업 자료의 안내 구조. 외부 프로젝트 코드·작품 파일은 복제하지 않았습니다.
