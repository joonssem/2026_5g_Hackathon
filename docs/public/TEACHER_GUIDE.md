# 교사 운영 안내

## 수업의 초점

“멋진 앱을 빨리 만들기”보다 실제 불편을 관찰하고, 친구의 생각을 듣고, 해결 방법을 비교하고, 선택을 설명하는 데 중점을 둡니다. 완성 기준은 핵심 기능 1개, 기준에 따른 직접 시험, 사고 과정과 작품 나눔입니다.

## 사전 준비

1. 실제 학생 교육용 계정으로 Canva Code 생성부터 게시까지 시험합니다. 학교 계정의 AI 권한·사용량을 확인합니다.
2. iPad에서 GitHub Pages 안내 웹, Canva, Padlet 접속을 확인합니다.
3. 하나의 Padlet에 반별 섹션을 만들고, 각 섹션으로 연결되는 제출 양식 링크를 `config.js`의 `padletClassLinks`에 넣습니다. 제출 중 수동 승인을 켜고 승인하지 않은 시범 글이 다른 학생에게 보이지 않는지 확인합니다.
4. Canva 문서(Docs)를 만들고 조원의 학교 계정을 편집 가능으로 초대합니다. 두 아이패드에서 같은 문서를 열어 글 수정과 요청문·링크 복사가 되는지 시험합니다. 학생의 초대 권한이 제한되면 교사가 문서를 만들고 조원을 초대합니다.
5. Code 사용이 막힌 경우를 위해 교사용 예시 도구와 종이 입력·버튼·결과 설계 방법을 준비합니다.

## 팀 편성

기본 2인, 필요하면 3인입니다. 첫 단계에서 학생이 교사와 정한 인원을 선택합니다. 3인 선택 시 세 번째 학생의 문제 장면과 추가 발언 순서가 나타납니다. 인원을 바꿔도 기존 기록을 지우지 않습니다.

1번은 안내·기록, 2번은 Canva 조작, 3번은 질문·시험을 맡습니다. 2인 팀은 1번이 시험을 맡습니다. 기기를 맡은 사람이 혼자 결정하지 않도록 모든 학생이 해결 방법을 제안하게 합니다. 글을 쓰기 어려운 학생은 말하기·그림·선택으로 의견을 내고 기록 담당이 옮길 수 있습니다.

1번·2번·3번은 팀 안의 역할 순서이며 출석번호가 아닙니다. 3인 팀도 두 아이패드로 활동하며 3번은 1번 화면을 함께 봅니다.

## 진행표

| 차시 | 시간 | 활동 | 교사의 지원 |
| --- | --- | --- | --- |
| 1 | 0–4분 | 함께 출발 | 첫 화면을 함께 읽고 목표·역할·두 차시 흐름 안내 |
| 1 | 4–12분 | 불편 발견 | “언제? 무엇 때문에?” 실제 장면을 묻기 |
| 1 | 12–18분 | 문제 선택 | 사용자·문제·선택 이유·원하는 변화 확인 |
| 1 | 18–27분 | 해결 탐색 | 방법 A/B 비교, 한 가지 선택 이유 듣기 |
| 1 | 27–40분 | 프롬프트 완성 | 입력·행동·출력·시험 기준, Canva 공유 문서 생성·조원 초대·요청문 확인 |
| 2 | 0–18분 | Canva 구현 | 받은 요청문으로 생성, 질문이 나오면 팀이 먼저 결정 |
| 2 | 18–26분 | 시험과 개선 | 성공 기준과 실제 결과 비교, 한 가지 수정 |
| 2 | 26–36분 | Padlet 나눔 | 게시 링크를 다른 iPad에서 확인, 문제·탐색·설명 함께 게시 |
| 2 | 36–40분 | 돌아보기 | 생각 변화와 친구 기여 말하기, 기록 저장 |

교실 상황에 따라 교사가 조정하는 권장 시간입니다. 자동 타이머나 강제 이동은 없습니다. 1차시가 별도 날짜라면 같은 브라우저를 쓰고 기록 파일도 남깁니다.

5단계 13분에는 요청문 검토와 문서 공유가 모두 포함됩니다. 수업 전 학교 계정으로 초대를 시험하고, 시간이 빠듯하면 교사가 공유 문서를 미리 준비합니다. 초대가 막히면 교사가 문서를 만들어 두 기기의 계정을 초대합니다.

## 첫 4분 안내 예시

먼저 교실 앞 전자칠판에서 `teacher.html`의 6장 안내를 진행합니다. 마지막 장의 QR코드를 1번 아이패드 카메라로 스캔해 학생 활동 화면의 1단계부터 시작합니다. Canva 공유 문서는 요청문을 정리하는 5단계에서 만들거나 미리 준비한 문서를 엽니다. 실제 학생 활동 주소와 반별 Padlet 제출 링크는 사용자 요청에 따라 유지합니다.

학생용 화면과 별도의 전자칠판 안내는 1920px 너비에서 일반 제목 약 77px, 마지막 장 제목 약 61px, 주요 설명 약 42~48px입니다. 실제 물리적인 글자 크기는 전자칠판의 해상도·배율에 따라 다르므로 수업 전 뒷자리에서 확인합니다.

학생 iPad 10세대 화면은 본문 18px, 질문·입력 20px, 제목 32~42px로 조정했습니다. 보조 설명도 16px로 높였습니다. 세로 화면에서는 카드가 한 열로 배치되며 내용은 세로로 스크롤합니다. 요청문 역시 18px로 표시합니다. 학생은 전자칠판 발표 화면이 아닌 `index.html`에서 기록합니다. 교사 개인 준비 사항은 **교사용 메모** 버튼에 있습니다.

“오늘은 AI에게 그냥 만들어 달라고 하기 전에 우리가 해결하고 싶은 문제를 충분히 이야기할 거예요. 첫 시간에는 생각을 정리하고, 다음 시간에는 그 생각으로 실제 도구를 만들어요. 1번은 질문과 기록, 2번은 Canva, 3번이 있다면 질문과 시험을 맡아요. 역할이 달라도 생각은 모두 말해요. 완성할 기능은 하나면 충분해요. 실명이나 사진은 넣지 않아요.”

## 관찰 질문

- 불편을 특정한 장면과 사람으로 설명할 수 있는가?
- 다른 팀원의 생각을 듣고 질문하거나 의견을 바꾸는가?
- 두 해결 방법을 비교하고 선택 이유를 말할 수 있는가?
- 프롬프트에 입력·행동·출력·성공 기준이 구체적인가?
- 생성된 도구를 기준에 따라 시험하고 실제 결과를 설명하는가?

## 제작과 시험 기기

**2번 아이패드에서 Canva 제작·게시 → Canva 공유 문서의 실행 링크 칸에 기록 → 1번 아이패드에서 링크를 열어 직접 시험**합니다. 3인 팀의 3번은 1번 화면에서 같은 문서를 보고 함께 시험합니다. 안내 웹은 그대로 두고 실행 링크를 새 탭으로 열어 오갑니다.

수정이 필요하면 1번이 안내 웹의 시험 결과·고칠 점을 공유 문서에도 붙여 넣습니다. 2번이 이를 확인해 같은 Canva Code 대화에서 수정하고 다시 게시합니다. 주소가 바뀌면 공유 문서의 실행 링크도 갱신합니다. 1번은 링크를 다시 열거나 새로고침하여 재시험합니다. 최종적으로 1번에서 시험한 실행 링크를 Padlet에 올립니다. 테스트용 최초 게시도 개인정보를 먼저 확인합니다.

## Canva 공유 문서 만들기와 조원 초대

1. 1번이 학교 계정으로 Canva를 열고 문서(Docs)를 만듭니다. 문서 제목은 `팀 이름_공유문서`로 정하며, 교사가 미리 준비했다면 그 문서를 엽니다.
2. 문서의 **공유**에서 2번의 학교 Canva 계정을 찾아 **편집 가능** 권한으로 초대합니다. 계정 정보는 Canva의 초대 화면에서만 사용합니다.
3. 2번이 자기 계정에서 초대 알림을 확인하고 같은 문서를 엽니다. 두 아이패드에서 짧은 글을 서로 적어 공동 편집을 확인합니다. 3번은 1번 화면을 함께 보며, 별도 기기를 쓰는 경우 그 계정도 초대합니다. 초대가 안 되면 교사가 도와줍니다.
4. 문서에 **요청문 / 실행 링크 / 시험 결과·고칠 점** 칸을 만듭니다. 요청문은 안내 웹에서 복사해 넣고, 2번은 같은 문서에서 복사해 Canva Code에 붙여 넣습니다.
5. 실행 링크와 수정 요청도 같은 문서에 기록합니다. 문서 사본을 따로 만들지 않고 계속 같은 문서를 사용합니다.

안내 웹의 기록은 Canva 문서에 자동으로 동기화되지 않습니다. 수정한 요청문이나 시험 기록은 필요한 칸에 다시 복사하고, 마지막에는 기록 전체를 복사해 문서에 보관할 수 있습니다. 조원용 공유 문서와 Padlet에 올릴 최종 웹앱은 구분합니다. Padlet에는 웹앱의 게시된 실행 주소를 넣습니다.

요청문의 ‘로그인·외부 서비스 연결 없이’ 조건은 학생이 제작할 웹 도구의 기능 범위입니다. 수업에서 Canva에 로그인하고 문서를 공동 편집하는 절차와는 구분합니다.

공식 안내: [Canva Docs 공동 작업과 공유](https://www.canva.com/help/share-publish-docs/), [공유 권한 설정](https://www.canva.com/help/share-via-link-or-email-variantb/). 실제 학교 계정의 초대 제한과 iPad 화면은 수업 전에 확인합니다.

06단계에는 Canva 홈에서 AI를 찾는 위치를 넣었습니다. Safari 웹 화면은 왼쪽 메뉴, 모바일 앱 화면은 아래쪽 메뉴에서 Canva AI를 찾고, 없으면 More(더 보기)를 확인합니다. 이후 입력창의 코드(Code)를 선택합니다. 실제 UI는 계정·버전에 따라 다를 수 있으므로 교사가 사전 확인합니다.

근거: [Canva AI 공식 위치 안내](https://www.canva.com/help/new-canva-ai/), [Canva 모바일 앱 안내](https://www.canva.com/help/navigate-canva-mobile-app/).

## Padlet 제출·공개 운영

`padletClassLinks`는 1~4반의 제출 양식, `padletViewUrl`은 추후 전달받을 학생용 5학년 전체 보기 주소입니다. 반별 소회의실 주소는 공개 GitHub의 설정·소스·테스트·문서에 기록하지 않습니다. 교사가 별도로 전달받고, 학생에게 필요한 시점에 직접 안내합니다. 교사용 메모도 학생이 열 수 있으며 교사 인증 기능이 없습니다.

제출이 끝나면 교사가 게시물을 승인하고 별도로 감상 링크를 안내합니다. 학생은 그 링크에서 작품을 써 보고 댓글과 좋아요를 남깁니다. Padlet에서 학생의 댓글 권한과 좋아요 반응을 허용합니다. 제출 중 작품을 숨기는 것은 Padlet의 수동 승인과 승인 보류로 관리합니다. 소회의실 링크는 교사 관리 권한을 부여하지 않으며 승인 작업은 권한이 있는 교사 계정으로 진행합니다.

하나의 Padlet에 반별 섹션을 만듭니다. 교사는 전체 게시판에서 모든 반의 제출물을 확인합니다. 학생에게는 전체 게시판 주소 대신 **해당 반의 제출 양식 링크**를 안내합니다. `config.js`의 `padletClassLinks`에 반별 링크를 등록하면 학생 화면에 반 선택과 해당 반 제출 버튼이 표시됩니다. 링크가 준비되지 않은 반은 교사 안내를 표시하며 다른 반이나 전체 게시판으로 보내지 않습니다.

반별 제출 양식을 사용할 경우 각 반 섹션을 지정합니다. 학생은 양식에서 글을 제출하고, 결과 감상은 별도 보기 링크로 진행합니다. **제출 후에도 다른 팀 글을 보지 않도록 제출 후 동작을 확인 메시지 또는 재제출로 설정하고 전체 게시판으로 이동시키지 않습니다.** 수동 승인도 함께 사용해 공개 시점을 관리합니다. Padlet 설정 → 콘텐츠 → 검토(Moderation) → 수동(Manual)을 선택하고, 제출 마감까지 승인을 보류합니다. 교사는 전체 게시판에서 승인 대기 글까지 확인합니다. 실제 학생 기기 두 대로 서로의 글이 보이지 않는지 미리 시험합니다.

마감 후 공개할 기존 게시물을 승인합니다. 설정만 끄는 것으로 이미 대기 중인 글까지 공개된다고 가정하지 않습니다. 5학년 전체 결과는 추후 전달할 **학생용 감상 링크**로 안내하며, 그때 `padletViewUrl`에 넣습니다. 댓글·좋아요 활동 중에는 방문자 권한을 **댓글 작성자(Commenter)**로 바꾸고 댓글·반응을 켭니다. 새 게시물은 받지 않고 기존 작품에 의견을 남길 수 있습니다. **읽기 전용(Reader)은 댓글·반응도 허용하지 않으므로 감상 활동까지 끝난 뒤 필요할 때 적용합니다.** 이 웹페이지는 Padlet의 승인·권한을 변경하지 않습니다.

공식 근거: [제출 양식과 소회의실의 차이](https://padlet.blog/share-links/), [게시물 숨기기와 수동 승인](https://padlet.help/l/en/article/27gow0dbq7-how-can-i-hide-posts), [방문자 권한별 기능](https://padlet.help/l/en/article/l2d9pcbd9i-privacy-settings).

## Padlet 제출 구조

Padlet 게시도 **1번 아이패드**에서 합니다. 8단계에 제목·웹앱 링크·내용을 구분하고 각각 복사 버튼을 제공합니다.

공유 문서의 최종 실행 링크를 안내 웹의 웹앱 주소 칸에 붙여 넣고 반·팀 이름·내용·개인정보를 먼저 확인합니다. 제출 양식을 새 탭으로 열고, 아래 항목을 하나씩 복사해 양식에 넣은 뒤 최종 확인하여 게시합니다.

1. **제목:** 반과 팀 이름만 입력합니다. 예: `5학년 1반 · 초록 톱니`. 이름과 출석번호는 넣지 않습니다. 반·팀 이름은 첫 단계에서 적고 제출 단계에서 보완할 수 있습니다.
2. **링크 첨부:** Canva로 만든 최종 웹앱 실행 주소를 별도로 넣습니다. 1번에서 시험한 게시 주소를 사용합니다.
3. **내용:** 1번 아이패드에 모인 문제·문제 선택 이유·해결 방법 A/B·선택한 방법과 이유·웹앱 설명·사용 방법을 복사하여 Padlet 내용 칸에 붙여 넣습니다. 시험 결과와 고치기 기록이 있으면 함께 포함합니다.

설명은 5단계에서 작성한 내용을 불러오며 실제 결과에 맞게 수정할 수 있습니다. 기록이 빠지면 해당 단계로 돌아가 보완합니다. 웹은 자동 게시하지 않습니다.

## 문제 상황 대응

- 아이디어가 없으면 학교 하루의 장면을 떠올리게 하고 도구 예시를 정답처럼 정해 주지 않습니다.
- 입력이 많으면 긴 문장 대신 핵심 구절로 적고 먼저 말하게 합니다. 교사가 단계 이동을 막는 체크를 요구하지 않아도 됩니다.
- 코드 생성이 오래 걸리면 연속 제출하지 않고 시험 순서를 이야기하게 합니다.
- AI 권한·사용량 문제가 있으면 교사용 예시를 시험하고 종이 화면 설계·요청문을 결과로 남깁니다.
- 게시가 막히면 편집 링크를 공개하지 말고 허용된 화면 캡처·설명·교사 시연으로 대체합니다.
- 자동 저장 불가 표시가 뜨면 전체 기록을 복사·내보내기 합니다. 다른 아이패드에는 자동으로 기록이 옮겨지지 않습니다.
