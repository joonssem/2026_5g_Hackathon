# 제작·판단 기록

## 2026-10-22 · 요구사항 확인

- 대상: 초등학교 5학년, 학생과 담당 교사 대부분 Canva Code 첫 사용.
- 시간: 1차시 40분 + 2차시 40분. 연속 운영을 기본으로 하되 별도 날짜에도 브라우저 기록으로 이어갈 수 있도록 구성.
- 기기: iPad 10세대. 1번은 안내·기록, 2번은 Canva 조작. Canva 공유 문서에 조원을 초대해 요청문·링크·수정 요청을 함께 확인.
- 팀: 기본 2인, 당일 상황에 따라 3인 선택. 3번은 질문·시험 역할을 맡되 모든 팀원이 문제 발견과 해결 탐색에 참여.
- 핵심: 바이브 코딩 결과뿐 아니라 대화를 통한 문제 발견·해결 탐색·프롬프트 발전 과정 자체를 학습.
- Padlet 제출: 결과물 링크, 조원이 생각하는 문제, 해결하기 위해 생각한 것, 웹앱 설명.
- 디자인: 뉴모피즘. 제목·강조 Ria, 본문 Paperozi. 사용자 제공 CDN 사용.
- 배포: GitHub 푸시 기반. 지정 저장소·게시판 주소 확인 필요.

## 학습 흐름

1. 교사가 첫 화면에서 목표, 전체 흐름, 역할, 참여 방법 안내.
2. 각 팀원이 실제 불편 장면 말하기. 3인 선택 시 3번 기록란 추가.
3. 사용자·문제·선택 이유·원하는 변화 정하기.
4. 다른 해결 방법 비교 후 방법과 선택 이유 기록.
5. 도구 이름·설명·입력·버튼 행동·출력·성공 기준을 정하고 요청문을 함께 검토.
6. Canva 공유 문서에 요청문을 붙여 넣고, 조원이 같은 문서에서 복사해 Canva Code에서 구현.
7. 성공 기준과 실제 결과를 비교하고 하나씩 개선.
8. 앞의 문제·탐색 기록을 다시 보며 웹앱 설명과 결과 링크를 합친 Padlet 글 생성.
9. 생각이 바뀐 순간 돌아보기, 기록 내보내기.

요청문은 학생 입력을 문장으로 조합합니다. 이 웹이 AI로 답을 대신 정해 주지 않습니다. 예시는 빈칸 안내로만 제공해 학생의 결정을 자동 대체하지 않습니다. 체크 미완료·빈칸으로 단계 이동을 막지 않아 교사가 속도를 조정할 수 있게 했으며, 프롬프트에는 미정 항목을 괄호로 보여 줍니다.

## 화면·접근성 판단

- iPad 웹 뷰포트의 세로 약 820×1180, 가로 약 1180×820을 목표로 반응형 구성. 브라우저 막대·화상 키보드 때문에 세로 스크롤은 허용.
- 연한 청회색 배경, 밝은 그림자와 어두운 그림자를 사용한 돌출 카드·버튼, 들어간 입력란·현재 단계.
- 뉴모피즘의 약한 경계를 보완하도록 텍스트 라벨, 현재 단계 표시, 포커스 테두리, 충분한 터치 영역을 사용.
- 입력 글자는 16px. 본문은 Paperozi, 큰 제목은 Ria. 외부 폰트 실패 시 대체 글꼴 유지.
- 3인 팀에 낙인 표현이나 편성 사유를 표시하지 않음. 말·그림·선택으로 참여할 수 있는 안내 제공.

## 구현 기록

- 설치·빌드 없는 정적 웹 작성. GitHub Pages 하위 경로 호환.
- 9단계 내비게이션, 교사용 모달, 초기화 확인 모달, 기기별 자동 저장 구현.
- 학생 문자열은 HTML에 넣을 때 이스케이프 처리. 복사·내보내기에는 텍스트만 사용.
- Clipboard API 실패 시 선택 복사 대안, Web Share 미지원 시 복사로 전환.
- Padlet 링크는 설정된 HTTPS Padlet 도메인만 허용. 미설정 시 교사 안내 표시.
- Ria/Paperozi 사용자 지정 폰트 추가.
- GitHub CLI의 기존 로그인은 인증 실패, 초기 Git 네트워크 요청은 로컬 프록시 연결 실패로 확인됨. 인증 정보는 문서나 소스에 기록하지 않음.
- 프로세스 단위 Git 설정으로 메타데이터 읽기는 성공. 로컬 `git init -b main` 성공 후 `git add`·`git commit`은 `.git/index.lock` 권한 거부로 실패. 권한을 우회하지 않았으며 커밋·푸시하지 못함.

## 2026-10-22 · 전자칠판·iPad 글자 크기 수정

- 추가 요구: 교사는 교실 앞 65인치 전자칠판으로 시작 안내, 학생은 iPad 10세대로 개별 활동.
- 하나의 화면을 단순 확대하면 안내 내용이 잘리므로 `teacher.html`에 6장 발표 화면을 구성. 핵심 문장을 줄이고 제목 약 77px·설명 42~48px(1920px 너비 기준), 화면 너비에 비례하도록 조정.
- 전체 화면 버튼·이전/다음·키보드 이동 구현. 준비물·계정 점검 등 교사 개인 참고는 기존 모달에 유지.
- 학생용 `typography.css` 추가: 본문·대화·요청문 18px, 질문·입력 20px, 보조 설명 16px, 제목 32~42px. iPad 세로 방향에서 카드 1열, 대화·표현의 줄바꿈 허용.
- Ria/Paperozi와 뉴모피즘 유지. 학생의 현재 기록이나 팀 인원은 발표 화면에서 변경하지 않음.
- 추가 요청에 따라 06단계에 Safari·앱별 Canva AI 위치, More 대안, Code 선택 안내를 추가. 공식 Canva 도움말에서 확인.
- 시험 방식 확정: 06단계에서 2번이 최초 게시·링크 전송, 07단계에서 1번 기기로 시험, 2번 수정·재게시 후 1번 재시험, 08단계에서 시험한 최종 링크 제출. 3인 팀도 1번 기기로 시험.
- Padlet 제출 형식 확정: 제목은 반·팀 이름(이름·출석번호 제외), Canva 웹앱 게시 주소는 별도 링크 첨부, 본문은 1번 아이패드의 대화·탐색·설명 기록 복사·붙여넣기. 반 입력란과 제목/링크/내용 각각의 복사 버튼을 추가하고 시험·개선 기록도 있으면 내용에 포함.
