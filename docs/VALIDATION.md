## 검증 범위의 한계

- 상태 테스트는 Node VM의 DOM 대체 환경에서 실행했습니다. 브라우저 렌더링·CSS·Safari 동작을 검증하는 테스트가 아닙니다.
- Chrome 첫 화면 열기는 확인했으나, 이후 뷰포트 변경과 재연결 요청이 시간 초과되어 820×1180/1180×820 스크린샷과 시각 검증을 완료하지 못했습니다. 반응형 CSS는 두 방향을 목표로 작성했습니다.
- 실제 iPad 10세대 Safari, 화상 키보드, 폰트 로딩, 시스템 공유·AirDrop·Teams 전송·Safari 다운로드는 수업 기기에서 확인해야 합니다.
- 실제 Canva 학생 계정으로 생성·게시와 Padlet 게시를 실행하지 않았습니다. 계정과 학교 설정에 따른 사전 시험이 필요합니다.
- Padlet 실주소는 아직 제공되지 않아 연결되지 않았습니다. 미설정 안내 상태는 검사했습니다.
- Git 로컬 저장소 초기화는 성공했지만 `git add`·`git commit`은 보호된 `.git/index.lock` 쓰기 권한 오류로 실패했습니다. 커밋·푸시·Pages 배포는 완료되지 않았습니다. 또한 GitHub CLI의 기존 인증은 유효하지 않은 상태입니다.

## 재검증 방법

### 전자칠판·글자 크기·시험 흐름 수정

- `node tests/teacher.mjs`: 전자칠판 6장 표시·이동 범위·키보드·전체 화면 미지원 안내 검사.
- 기존 `node tests/check.mjs`로 활동·복사·자동 저장·Padlet 연결 회귀 검사.
- 학생 글자 크기와 전자칠판 전용 CSS를 반영했으며, 실제 65인치 전자칠판 뒷자리 가독성과 iPad Safari의 시각 검증은 아직 필요합니다.
- 06단계 Canva AI 위치는 공식 도움말 기준입니다. 실제 학교 계정 UI는 사전 확인 대상입니다.
- Padlet 제출 형식 수정 후 두 테스트 모두 통과. 반·팀 이름의 제목 생성·변경 반영, 제목/웹앱 링크/내용의 개별 복사, 본문에서 링크를 분리하는 동작을 검사했습니다.

```powershell
node --check app.js
node --check config.js
node --check teacher.js
node tests/check.mjs
node tests/teacher.mjs
python -m http.server 8025 --bind 127.0.0.1
```

실제 기기에서는 HTTPS 배포 주소로 접속하고 아래를 확인합니다.

1. 가로·세로에서 입력란, 단계 메뉴, 다음 버튼에 가로 잘림이 없는지 확인.
2. 3인 선택 후 3번 기록란과 질문 순서가 나타나는지 확인.
3. 짧은 예시를 전 단계에 입력하고 새로고침 후 기록이 남는지 확인.
4. 프롬프트를 복사해 Teams로 2번에게 보내고 Canva에 붙여넣기.
5. Padlet 단계에서 문제·해결 방법 A/B·선택 이유·웹앱 설명·작품 링크 확인.
6. 실제 게시 링크를 다른 아이패드에서 열어 시험하고 Padlet에 게시.
7. 기록 내려받기 파일과 복사 대안 확인.
