# 교사 운영 안내

## 수업의 초점

“멋진 앱을 빨리 만들기”보다 실제 불편을 관찰하고, 친구의 생각을 듣고, 해결 방법을 비교하고, 선택을 설명하는 데 중점을 둡니다. 완성 기준은 핵심 기능 1개, 기준에 따른 직접 시험, 사고 과정과 작품 나눔입니다.

## 사전 준비

1. 실제 학생 교육용 계정으로 Canva Code 생성부터 게시까지 시험합니다. 학교 계정의 AI 권한·사용량을 확인합니다.
2. iPad에서 GitHub Pages 안내 웹, Canva, Teams, Padlet 접속을 확인합니다.
3. Padlet 주소를 `config.js`에 넣습니다. 게시판의 공개 범위, 학생 게시·댓글·교사 검토 설정을 정합니다.
4. Teams에서 짝에게 긴 텍스트를 보내고 받은 내용을 복사할 수 있는지 확인합니다.
5. Code 사용이 막힌 경우를 위해 교사용 예시 도구와 종이 입력·버튼·결과 설계 방법을 준비합니다.

## 팀 편성

기본 2인, 필요하면 3인입니다. 첫 단계에서 학생이 교사와 정한 인원을 선택합니다. 3인 선택 시 세 번째 학생의 문제 장면과 추가 발언 순서가 나타납니다. 인원을 바꿔도 기존 기록을 지우지 않습니다.

1번은 안내·기록, 2번은 Canva 조작, 3번은 질문·시험을 맡습니다. 2인 팀은 1번이 시험을 맡습니다. 기기를 맡은 사람이 혼자 결정하지 않도록 모든 학생이 해결 방법을 제안하게 합니다. 글을 쓰기 어려운 학생은 말하기·그림·선택으로 의견을 내고 기록 담당이 옮길 수 있습니다.

## 진행표

| 차시 | 시간 | 활동 | 교사의 지원 |
| --- | --- | --- | --- |
| 1 | 0–4분 | 함께 출발 | 첫 화면을 함께 읽고 목표·역할·두 차시 흐름 안내 |
| 1 | 4–12분 | 불편 발견 | “언제? 무엇 때문에?” 실제 장면을 묻기 |
| 1 | 12–18분 | 문제 선택 | 사용자·문제·선택 이유·원하는 변화 확인 |
| 1 | 18–27분 | 해결 탐색 | 방법 A/B 비교, 한 가지 선택 이유 듣기 |
| 1 | 27–40분 | 프롬프트 완성 | 입력·행동·출력·시험 기준, 팀원 검토 후 Teams 전달 |
| 2 | 0–18분 | Canva 구현 | 받은 요청문으로 생성, 질문이 나오면 팀이 먼저 결정 |
| 2 | 18–26분 | 시험과 개선 | 성공 기준과 실제 결과 비교, 한 가지 수정 |
| 2 | 26–36분 | Padlet 나눔 | 게시 링크를 다른 iPad에서 확인, 문제·탐색·설명 함께 게시 |
| 2 | 36–40분 | 돌아보기 | 생각 변화와 친구 기여 말하기, 기록 저장 |

교실 상황에 따라 교사가 조정하는 권장 시간입니다. 자동 타이머나 강제 이동은 없습니다. 1차시가 별도 날짜라면 같은 브라우저를 쓰고 기록 파일도 남깁니다.

## 첫 4분 안내 예시

교실 앞 65인치 전자칠판에서는 안내 웹 상단의 **전자칠판 안내**를 누르거나 `teacher.html`을 엽니다. 학생용 화면과 별도로 6장의 큰 글씨 화면을 제공합니다. 제목은 일반적인 1920px 너비에서 약 77px, 주요 설명은 약 42~48px입니다. 화면 너비에 맞춰 조절되며 4K 환경에서도 함께 커집니다. 실제 글자의 물리적 크기는 전자칠판 해상도·배율에 따라 다르므로 수업 전 뒷자리에서 확인합니다.

**전체 화면** 버튼을 누르고, 이전·다음 버튼이나 키보드 ←/→, PageUp/PageDown으로 넘깁니다. 약 4분 동안 목표 → 두 차시 흐름 → 역할 → 대화 약속 → 요청문 기준 → 시작 순서로 안내합니다. 마지막 화면에서 학생 활동 화면으로 이동할 수 있습니다.

학생 iPad 10세대 화면은 본문 18px, 질문·입력 20px, 제목 32~42px로 조정했습니다. 보조 설명도 16px로 높였습니다. 세로 화면에서는 카드가 한 열로 배치되며 내용은 세로로 스크롤합니다. 요청문 역시 18px로 표시합니다. 학생은 전자칠판 발표 화면이 아닌 `index.html`에서 기록합니다. 교사 개인 준비 사항은 **교사용 메모** 버튼에 있습니다.

“오늘은 AI에게 그냥 만들어 달라고 하기 전에 우리가 해결하고 싶은 문제를 충분히 이야기할 거예요. 첫 시간에는 생각을 정리하고, 다음 시간에는 그 생각으로 실제 도구를 만들어요. 1번은 질문과 기록, 2번은 Canva, 3번이 있다면 질문과 시험을 맡아요. 역할이 달라도 생각은 모두 말해요. 완성할 기능은 하나면 충분해요. 실명이나 사진은 넣지 않아요.”

## 관찰 질문

- 불편을 특정한 장면과 사람으로 설명할 수 있는가?
- 다른 팀원의 생각을 듣고 질문하거나 의견을 바꾸는가?
- 두 해결 방법을 비교하고 선택 이유를 말할 수 있는가?
- 프롬프트에 입력·행동·출력·성공 기준이 구체적인가?
- 생성된 도구를 기준에 따라 시험하고 실제 결과를 설명하는가?

## 제작과 시험 기기

**2번 아이패드에서 Canva 제작·게시 → Teams·메시지로 게시 링크 전송 → 1번 아이패드에서 직접 시험**합니다. 3인 팀도 3번이 1번과 함께 1번 아이패드에서 시험합니다. 안내 웹은 그대로 두고 실행 링크를 새 탭으로 열어 오갑니다.

수정이 필요하면 1번에서 기록한 요청을 2번에게 보냅니다. 2번이 같은 Canva 대화에서 수정하고 게시 내용을 갱신한 뒤 링크를 다시 보냅니다. 1번은 링크를 다시 열거나 새로고침하여 재시험합니다. 최종적으로 1번에서 시험한 실행 링크를 Padlet에 올립니다. 테스트용 최초 게시도 개인정보를 먼저 확인합니다.

06단계에는 Canva 홈에서 AI를 찾는 위치를 넣었습니다. Safari 웹 화면은 왼쪽 메뉴, 모바일 앱 화면은 아래쪽 메뉴에서 Canva AI를 찾고, 없으면 More(더 보기)를 확인합니다. 이후 입력창의 코드(Code)를 선택합니다. 실제 UI는 계정·버전에 따라 다를 수 있으므로 교사가 사전 확인합니다.

근거: [Canva AI 공식 위치 안내](https://www.canva.com/help/new-canva-ai/), [Canva 모바일 앱 안내](https://www.canva.com/help/navigate-canva-mobile-app/).

## Padlet 제출 구조

Padlet 게시도 **1번 아이패드**에서 합니다. 8단계에 제목·웹앱 링크·내용을 구분하고 각각 복사 버튼을 제공합니다.

1. **제목:** 반과 팀 이름만 입력합니다. 예: `5학년 1반 · 초록 톱니`. 이름과 출석번호는 넣지 않습니다. 반·팀 이름은 첫 단계에서 적고 제출 단계에서 보완할 수 있습니다.
2. **링크 첨부:** Canva로 만든 최종 웹앱 실행 주소를 별도로 넣습니다. 1번에서 시험한 게시 주소를 사용합니다.
3. **내용:** 1번 아이패드에 모인 문제·문제 선택 이유·해결 방법 A/B·선택한 방법과 이유·웹앱 설명·사용 방법을 복사하여 Padlet 내용 칸에 붙여 넣습니다. 시험 결과와 고치기 기록이 있으면 함께 포함합니다.

설명은 5단계에서 작성한 내용을 불러오며 실제 결과에 맞게 수정할 수 있습니다. 기록이 빠지면 해당 단계로 돌아가 보완합니다. 웹은 자동 게시하지 않습니다.

## 문제 상황 대응

- 아이디어가 없으면 학교 하루의 장면을 떠올리게 하고 도구 예시를 정답처럼 정해 주지 않습니다.
- 입력이 많으면 긴 문장 대신 핵심 구절로 적고 먼저 말하게 합니다. 교사가 단계 이동을 막는 체크를 요구하지 않아도 됩니다.
- 코드 생성이 오래 걸리면 연속 제출하지 않고 시험 순서를 이야기하게 합니다.
- AI 권한·사용량 문제가 있으면 교사용 예시를 시험하고 종이 화면 설계·요청문을 결과로 남깁니다.
- 게시가 막히면 편집 링크를 공개하지 말고 허용된 화면 캡처·설명·교사 시연으로 대체합니다.
- 자동 저장 불가 표시가 뜨면 전체 기록을 복사·내보내기 합니다. 다른 아이패드에는 자동으로 기록이 옮겨지지 않습니다.
